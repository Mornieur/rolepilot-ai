# Estratégia de IA

IA é consultiva e posterior a regras. Gemini Developer API gratuita é o runtime; OpenAI foi removido. Não há fallback pago e ChatGPT Plus é irrelevante para API. A quota gratuita pode usar conteúdo para melhorar produtos conforme política do provider; dados são minimizados. Análise manual atual continua elegível-only; override é futuro. Quota esgotada não para coleta, persistência ou filtro. Resultados nunca garantem contratação, inventam fatos ou enviam candidaturas.

Successful validated analyses are persisted as history per profile/job. Each row records provider, actual model, schema version `1`, timestamp, optional returned token usage and latency, and a hash of bounded normalized input. The raw prompt, raw provider response, provider errors, keys, and dollar-cost estimates are never persisted. A changed fingerprint marks the latest saved analysis stale; it remains visible and reanalysis is always an explicit single manual action.

Gemini output is accepted only after JSON parsing, a small provider DTO Zod contract, deterministic mapping/normalization, and the strict authoritative dossier Zod contract. Invalid output is never persisted or retried automatically; the prior saved analysis remains visible. The Gemini schema controls only essential shape, simple cardinality, and small enums; it never mirrors UUID, string, object-closure, or domain refinements. Provider cardinality is deliberately lower than the domain maximum. The mapper may shorten only explicitly presentation-oriented category labels and preparation topics at word boundaries, retaining the full topic rationale and logging only safe category counts. It never truncates factual text, URLs, identifiers, citations, compensation, or other semantic values; those provider/domain validation failures remain explicit and safe to diagnose. Internal schema-byte/depth/property budgets are regression guardrails, not claimed Gemini limits.

The model resolves from the optional `GEMINI_MODEL` override and otherwise uses the centralized `gemini-2.5-flash-lite` default. Persisted metadata and technical UI details show the actual resolved model. Development-only invalid-output diagnostics log only a safe classification, field path, expected/actual JSON categories where applicable, schema version, and model; they never log prompts, job/profile content, raw provider output, or credentials. String-length failures are distinguished as too short or too long and include only the configured bound and actual length. A max-token finish that leaves no parseable JSON is classified as incomplete output for manual diagnosis.

Opportunity Intelligence uses one bounded Tavily retrieval pass followed by two sequential Gemini structured syntheses: Company Intelligence (company, moment, compensation and hiring process) and Candidate/Application Intelligence (preparation, fit, career impact, positioning and questions). This split follows canary evidence: each section was accepted alone, but the cumulative schema failed at preparation with HTTP 400 INVALID_ARGUMENT. Call B receives job/profile/matching context and only the safe structured Company Intelligence result, never a second Tavily retrieval or all raw evidence. A fresh dossier therefore has two Gemini calls; a valid cache hit has zero. Both provider DTOs are parsed, deterministically merged with a server-owned timestamp, then passed through the unchanged authoritative Zod and citation validation before persistence. If either subcall fails, no completed or partial dossier is persisted. Each subcall has at most two attempts, with one retry only for timeout/network/429/503; invalid schemas and validation/citation errors never retry. Web pages are untrusted data, never instructions; the model may cite supplied evidence IDs only and cannot create URLs or unsupported facts.

Opportunity dossier reliability: both sequential syntheses resolve and use the same Gemini model, persisted as `synthesis_model`. A dossier becomes `completed` only in the database transaction that also inserts all validated sources: the completion RPC stages `pending`, inserts sources, then transitions to `completed` as its final statement; an error rolls back the entire transaction. A cache hit requires the exact profile/job row, completed status, valid dossier structure, at least one valid source, a non-expired 14-day TTL, and the exact current fingerprint. That fingerprint hashes relevant profile/job inputs plus centralized explicit contract, domain-schema, provider-schema and per-DTO versions; prompt/instruction and pt-BR output contract versions; retrieval and matching-context strategy versions; and the resolved synthesis model. It never stores prompt text. Old, malformed, source-less, expired, or incompatible dossiers are ordinary cache misses, never errors or provider-free hits.
